<objective>
Drop M3, M5, and M6a from the hierarchical Bayesian fan-out at the cluster
orchestrator level. Justification (from research doc Phase D-1 + user
decision Q2):

- M3 = M6b restricted to κ_share = 1 (verified by
  `test_wmrl_m6b_kappa_share_one_matches_m3` in
  `src/rlwm/fitting/models/wmrl_m6b.py:792`).
- M6a = M6b restricted to κ_share = 0 (verified by
  `test_wmrl_m6b_kappa_share_zero_matches_m6a`).
- M5 (= M3 + φ_rl) is dropped per user decision 2026-05-03; Collins 2025
  Methods, p.366 explicitly verifies that φ_rl is unnecessary.

The full M6b posterior on κ_share gives the Bayesian evidence about which
sub-model the data prefers — no need to fit the constrained models
separately for inference. All 7 models are still fit in MLE for the AIC
comparison table.

Purpose: Eliminate ~3 hours of cluster compute per pipeline run that was
producing R-hat = 1.60 / ESS = 7 misspecification artefacts on M3 / M5 / M6a.

Output: Narrowed default Bayesian fan-out, single source-of-truth config
constant, optional override path preserved for sensitivity work.
</objective>
